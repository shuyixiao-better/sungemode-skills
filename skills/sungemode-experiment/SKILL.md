# 行动实验｜先试一下

默认简体中文；遵从用户明确的语言偏好。验证会改变决策的假设，不把开发工作量当作验证结果；本技能可以独立使用。

## 工作方法

1. 读取已有机会判断及证据；否则从用户描述提取假设、客户、约束。确定可投入时间、现金上限、可招募对象和希望做的决定。最多集中问三个关键问题；未知约束给条件计划，不替用户承诺预算。
2. 选择一个致命假设，用 H 编号写成可被观察推翻的命题。区分“有痛点”“愿付费”“能触达”“能交付”；一轮实验只优先回答一个问题。
3. 按假设选择访谈、样品试用、人工交付、预售意向或其他最小方式。付费假设应观察支付或可信购买承诺；点赞、浏览和口头夸奖只能作为弱证据。预售承诺、收款、对外联系需遵从用户实际授权，计划里不要写成已经完成。
4. 默认七天；用户给出其他周期时遵从。逐日列出动作、产物、负责人、时间和现金成本，给招募不足时的备用方案。计算累计投入，包含准备、招募、交付和复盘，不能超过上限。
5. 在执行前确定一项主要指标、分子/分母、样本的招募方式、继续/调整/停止阈值及观察日期。注明阈值是本轮约定；样本不足应判为证据不足，不强行算转化率或制造统计显著性。
6. 给出记录结果的表格及下一次复盘问题。明确实际结果尚未产生，支持指标只能辅助解释，不替换主要指标。没有客户渠道时先验证触达，不能预设七天必有成交。

## 输出与记录

使用 [实验模板](assets/experiment.md) 输出假设、设计、逐日行动、累计预算、预设阈值与实际结果栏。停止条件包含达不到指标和触及预算/时间边界；结尾给今天能开始的动作。

用户要求保存/更新时写 `.sungemode/projects/<project-slug>/experiment.md` 或指定路径，并更新已有索引。读取旧实验，保留原始阈值及版本；若需改阈值，记录原因并另开实验，不能事后把失败改成达标。
