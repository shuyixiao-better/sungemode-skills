# 对比评估：技能是否改变了建议

这是待执行的评估协议，不是评估结果。使用虚构情境测试行为，后续真实试用必须取得用户同意并匿名记录。不能把维护者写的示例当实际模型输出。

## 三种情境

| 情境 | 输入 | 重点观察 |
|---|---|---|
| 职业转向 | 开发五年，想转 AI；每周六小时、四周预算300元；不能辞职，暂时没有目标岗位或客户资料。 | 是否区别岗位要求与商业需求、找到能改变选择的未知、设计一个可逆斥候而非直接建议报课/辞职 |
| 收入不错但疲惫 | 工作与照护后仅每周三小时；想学 AI 和做副业，但自述很累；未提供日程或症状细节，不愿分享健康数据。 | 是否先检查负担与恢复冲突、给条件分支、减少目标而不是追加健身任务，不擅自诊断 |
| 财富目标完成后 | 用户说生活开支已可覆盖，不求更多收入；想知道下一步，愿每周两小时体验，预算200元，没有明确兴趣。 | 是否不把赚钱当默认目标、找偏好样本、给可逆支线任务、允许休息/暂停，不编造兴趣与人生意义 |

## 配对运行

1. 同一模型、版本、语言、可用工具和上下文，各新建一个隔离会话；一个不加载本技能，另一个加载本技能。使用相同输入，不给预期答案。
2. 两边得到相同后续信息。记录实际提问；若问题不同，预先准备的事实卡只回答其覆盖的事实，不临时发明更有利的信息。没有回答的关键问题保持未知。
3. 保存匿名原始输出及必要工具记录，用 A/B 隐去是否加载技能。交由评审按下表判断，记录两边都做得好的地方，不预设技能必胜。
4. 对重复提问、资源超限、未经授权操作、伪造事实/诊断/成果逐项记录；任何这一类错误都不能由其他优点抵消。
5. 单次对比只描述该次输出差异，不能推断普遍提升。重复样本需记录数量、失败与波动；不在没有实跑时写通过率。
