# 技能行为评估

自动检查验证包结构和安装行为；此处的案例用于在实际 Agent 中检验决策表现。**仓库不声称这些案例已经在所有工具中通过。** 英文说明见 [English](README.en.md)。

从 [cases.json](cases.json) 选择案例，使用新的临时项目/会话加载目标技能，把 `prompt` 作为用户请求。按 `expectations` 检查实际输出，保存匿名报告，写明工具、版本、模型、安装语言、可用工具、日期和失败项。中文场景也可用英语等价改写来测试英文安装。

评估需要记录实际结果：

| 案例 | Agent/版本/模型 | 语言/联网能力 | 通过的要求 | 失败或未验证 | 输出记录 |
|---|---|---|---|---|---|

通过应建立在观察到的行为上。遇到外部实际操作要求时，用草稿和模拟数据评估，不真实发送、收款或发布。不要把“没看到错误”计为通过。

重点观察：是否保留未知、是否给可执行动作、累计预算是否成立、停止条件是否预先明确、复盘是否保留分母和原阈值、存档是否保留旧记录。发现问题时修改最相关的指令并重新运行受影响案例，不通过增加大量泛化禁令来掩盖问题。

新增七主题案例覆盖：未知资料、共享资源冲突、窄范围关系问题、反对意见、穿戴估算、集中配置、多模型一致、人生复盘历史、零净支出和离线引语。`life-review-preserves-history` 的文件描述需先在临时目录真实建成 fixture，再提供实际反馈，检查文件内容与历史。示例文档由维护者编写，不能计作行为评估通过。
