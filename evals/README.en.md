# Behavioral evaluation

Automated checks cover package structure and installation. These scenarios evaluate decisions in an actual agent. **The repository does not claim all cases have passed in every product.**

Choose a scenario from [cases.json](cases.json), load the target skill in a fresh temporary project/session, and submit its `prompt`. Check observed output against `expectations`. Save anonymized reports with tool/version/model, installation language, available tools, date, and failures. Translate Chinese prompts equivalently when testing English installations.

| Case | Agent/version/model | Language/browsing | Requirements passed | Failed/unverified | Output record |
|---|---|---|---|---|---|

Passes need observable behavior. Use drafts and fictional data for scenarios mentioning external actions; do not send, charge, or publish. Absence of visible errors is not a pass.

Check unknowns, executable actions, total budget, preset stop rules, review denominators/original thresholds, and preserved records. Make targeted instruction changes and rerun affected scenarios rather than accumulating broad prohibitions.
